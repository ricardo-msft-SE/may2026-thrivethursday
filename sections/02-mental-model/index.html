Section 02

The Foundry mental model in one page

Target timing

4 minutes

Goal: give the audience a structure so the UI feels obvious instead of crowded.

Explain Foundry as a lifecycle: define an agent, connect it to data and actions, protect it with controls, then observe and improve it.

Core map

What each surface does

Agent

The agent is the operating behavior: instructions, model choice, tool access, and grounded knowledge working together.

Models

Models provide reasoning and generation. For this audience, present them as the engine, not the whole vehicle.

Knowledge and data

This is where the agent stops being generic. Grounding lets it answer with enterprise context instead of just general training data.

Tools

Tools let the agent do work, not just talk. Use this section to separate “knows about” from “can act on.”

Guardrails

Guardrails are the control layer: content safety, boundaries, and operational confidence.

Traces and evaluation

These answer the enterprise question: how do we know what happened and how do we improve it?

Talking points

Speaker bullets

  • An agent is the composition layer, not just a prompt.
  • Models provide capability, knowledge provides relevance, tools provide action.
  • Guardrails, traces, and evaluation are what make the platform operationally serious.
  • The UI navigation mirrors this lifecycle.

Short script

Presenter-ready wording

One of the easiest ways to get lost in an AI platform is to treat every menu item as separate. Instead, think of Foundry as a workflow. You define an agent, give it a model, connect it to knowledge and tools, place guardrails around it, and then inspect and evaluate what it does. Once the audience sees that lifecycle, the UI becomes much easier to follow.
