Section 01

Why Foundry matters before we touch the UI

Target timing

3 to 4 minutes

Goal: align the audience on what Foundry is and what they are about to see live.

Microsoft Foundry gives teams one place to build, ground, observe, and improve AI agents without forcing them to stitch together disconnected services by hand.

What to say

Audience framing

Foundry is not just model access

Position it as the place where teams move from raw model capability to real agent behavior with knowledge, tools, safety, and evaluation.

Show the lifecycle, not a single prompt

The audience should leave understanding that agent creation is only one part of the story. The platform also covers grounding, observation, and iteration.

Keep the first half platform-centric

Avoid dropping into one narrow business scenario too early. First build the mental model so the later hands-on exercise makes sense.

Use the UI as proof

Each live switch should confirm a concept the audience has already heard, rather than introducing a concept and interface at the same time.

Narrative spine

Three promises to make up front

Build

You can create a working agent quickly, define its role, and start testing it in the same product surface.

Ground

You can connect the agent to trusted enterprise knowledge and tools so it answers with context and can take action.

Improve

You can inspect traces, evaluate outcomes, and refine the agent instead of treating it like a black box.

Operationalize

The end state is not a clever demo prompt. It is an agent that teams can observe, govern, and evolve.

Talking points

Speaker bullets

  • Foundry is the workspace where models become usable enterprise agents.
  • Today I’ll show the full loop: create, connect, test, observe, and improve.
  • The first half is platform overview; the second half shifts into a basic hands-on AI Search exercise.
  • As we move through the UI, map each screen to one of those jobs.

Short script

Presenter-ready wording

When people first hear about Foundry, they often think of it as a place to access models. That is part of the story, but not the interesting part. The interesting part is that Foundry brings together the pieces required to turn a model into an agent your team can actually trust and improve. In the next few minutes I’ll show you how the platform supports that full lifecycle, and then I’ll switch into the UI to prove each piece live.

Live switch

What to show next in Foundry

Primary transition

Move into the Foundry UI and orient the audience: point to the left navigation and the agent workspace tabs so they can see that the platform covers more than chat.

  • Left nav: Agents, Models, Tools, Knowledge, Data, Evaluations, Guardrails
  • Agent workspace: Playground, Traces, Monitor, Evaluation
  • Explain that these are the surfaces you will connect back to throughout the session

Fallback line

If the UI is slow, stay on this page and say: “Even if we pause the live environment for a moment, the key point is that Foundry is organized around the full agent lifecycle, not a single prompt window.”

Presenter note

Do not start with setup steps. Start with the audience mental model, then use the UI to reinforce it.
