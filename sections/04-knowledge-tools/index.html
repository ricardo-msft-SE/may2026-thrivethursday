Section 04

Ground the agent and let it act

Target timing

5 to 6 minutes

Goal: make the difference between knowledge and tools feel obvious.

This is the section where the audience should start seeing why an agent is more than a chat interface.

Simple distinction

Knowledge answers. Tools act.

Knowledge

Use knowledge when you want the agent grounded in trusted material like files, policies, or indexed enterprise content.

Tools

Use tools when the agent needs to call a system, trigger an operation, or retrieve live information from another source.

Best audience phrasing

Tell the audience: knowledge helps the agent know better, tools help the agent do more.

Bridge to exercise

This section tees up the later hands-on exercise where the agent answers questions grounded in files via AI Search.

Talking points

Speaker bullets

  • Knowledge is about trust and relevance.
  • Tools are about action and integration.
  • A strong agent usually needs both.
  • The later lab uses files in AI Search as a concrete grounding example.

Short script

Presenter-ready wording

Here is where the platform becomes useful in a business setting. If I only give the agent instructions, it is still generic. If I give it knowledge, it becomes grounded in what my organization actually knows. If I give it tools, it can go beyond answering and start interacting with systems. For most real scenarios, you want both of those dimensions.

Live switch

What to show in the UI

  • Open the Tools area and show one preconfigured connection or capability.
  • Open Knowledge and show a prepared source so you are not waiting on indexing live.
  • Return to Playground and ask one question that clearly uses grounding or a tool.
